# SRT ⇄ Script Compare

Инструмент для сверки SRT-субтитров с утверждённым сценарием (Word) и сборки
исправленного SRT-файла. **Тайм-коды и разбиение на блоки остаются нетронутыми —
меняется только текст.**

Заменяет ручной процесс «скопировать текст из SRT → почистить от тайм-кодов →
сравнить на anytexteditor.com → вручную перенести правки в SRT» одним экраном:
вставили два текста → нажали «Сравнить» → кликами выбрали нужные правки →
скачали готовый SRT.

## Как пользоваться

1. Откройте `index.html` в браузере (или опубликуйте на GitHub Pages — см. ниже).
2. **Слева** вставьте содержимое SRT-файла целиком (с номерами и тайм-кодами)
   или загрузите `.srt`.
3. **Справа** вставьте текст сценария из Word — только текст, который звучит
   в видео (колонку Script), без заголовков таблиц. Либо загрузите `.docx` —
   текст извлечётся автоматически (зачёркнутые фрагменты будут отброшены,
   маркированные списки получат «•»). После автоизвлечения удалите лишние
   строки (названия разделов и т.п.).
4. Нажмите **«Сравнить»**. Ниже появится текст с подсветкой:
   - красное зачёркнутое — убирается из SRT;
   - зелёное — добавляется из сценария;
   - серые метки `12` — номера блоков субтитров, чтобы быстро найти место.
5. **Клик по любой подсветке включает/выключает правку.** Это важно: сценарий
   не всегда прав (номера моделей, URL, телефоны, реально произнесённые слова
   чаще правильнее в SRT) — такие правки просто выключите.
6. Готовый SRT формируется в нижнем поле автоматически. **«Скачать .srt»** —
   и файл готов (имя: `исходное_имя_CORRECTED.srt`).

## Правила, заложенные в инструмент

Выведены из практики сверки обучающих видео (Harley-Davidson LMS):

- Тайм-коды не изменяются никогда; нумерация блоков в результате идёт заново с 1.
- «Умные» кавычки/апострофы (’ “ ”), неразрывные пробелы и символ «…» не
  считаются различиями — в результате остаётся вариант написания из SRT.
- Зачёркнутый текст в `.docx` = вырезанные из видео фрагменты, отбрасывается
  при импорте.
- Маркированные списки из `.docx` переносятся с маркером «•»; маркер на границе
  блоков субтитров прикрепляется к следующему блоку.
- Одиночные тире сценария («--», «—», «–») превращаются в « - ».
- Длинные фрагменты (8+ слов), которые есть в SRT, но отсутствуют в сценарии
  (вступления, представления спикеров), по умолчанию **не** удаляются —
  включите такую правку кликом, если удалить всё же нужно.
- Переносы строк внутри блока сохраняются на исходных позициях; заменяющие
  слова наследуют строку заменяемых. Если из-за правок строка «слиплась»,
  блок автоматически перебивается на исходное число строк.
- Пустые блоки (в т.ч. «хвостовые» с нулевой длительностью) удаляются из
  результата (отключается галочкой).

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите в него содержимое этой папки
   (файл `index.html` должен лежать в корне).
2. В репозитории: **Settings → Pages → Source: Deploy from a branch →
   Branch: `main`, папка `/ (root)` → Save**.
3. Через минуту сайт будет доступен по адресу
   `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Можно и без GitHub: просто откройте `index.html` локально двойным кликом.

## Приватность

Всё работает в браузере, никакие файлы никуда не отправляются. Интернет нужен
только один раз — чтобы подгрузить библиотеку
[mammoth.js](https://github.com/mwilliamson/mammoth.js) (чтение `.docx`) с CDN.
Если открыть страницу без интернета, всё будет работать, кроме загрузки
`.docx` — текст сценария можно вставить вручную.

## Тесты

```bash
node tests/test.js
```

Проверяются: разбор SRT, дифф, привязка замен к блокам и строкам, буллиты на
границах блоков, поведение длинных удалений, удаление пустых блоков,
перенумерация.

## Структура

```
index.html      — страница приложения
css/style.css   — стили
js/app.js       — логика (парсер SRT, дифф Майерса по словам, сборка результата)
tests/test.js   — тесты для Node.js
```
